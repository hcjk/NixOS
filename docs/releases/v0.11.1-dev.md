# NexOS v0.11.1-dev — dual-boot installer and progress display

This corrective prerelease fixes installed systems that stopped after the ISO
was removed when the machine or VM used legacy BIOS firmware. It also makes
the destructive installation process visible through a nine-step progress
bar.

## Root cause and fix

The v0.11.0 in-OS installer created a BIOS-reserved GPT partition but only
copied the UEFI fallback loader. UEFI installations booted correctly, while a
VMware or physical machine configured for legacy BIOS had no executable MBR
stage and could hang immediately after selecting the hard disk.

The installer now:

- embeds Limine's HDD boot image and `limine-bios.sys` in the release ISO;
- preserves the protective-MBR partition metadata while installing Limine
  stage 1;
- writes Limine stage 2 into the dedicated GPT BIOS boot partition;
- installs `limine-bios.sys` and a root `limine.conf` on the FAT32 ESP;
- retains `EFI/BOOT/BOOTX64.EFI` for UEFI firmware; and
- reads back and compares both BIOS stages and all boot files before success.

## Installation display

`nex-install` now reports a percentage bar for nine named steps:

1. target and payload validation;
2. protective MBR and GPT creation;
3. FAT32 ESP formatting;
4. kernel and boot-file copying;
5. legacy BIOS stage installation;
6. NexFS root formatting;
7. storage-cache flushing;
8. byte and metadata verification; and
9. completion.

Progress is shown on both the framebuffer terminal and COM1 serial console.

## Verification

- The original legacy-BIOS hang was reproduced with the v0.11.0 installed
  disk under QEMU SeaBIOS.
- A new 256 MiB AHCI disk was installed from the v0.11.1 hybrid ISO while all
  nine progress steps were observed.
- The installer verified the kernel, UEFI loader, BIOS system file, root and
  UEFI configurations, MBR stage, GPT BIOS-stage bytes, GPT metadata, and
  NexFS UUID.
- After removing the ISO, the same disk booted NexOS 0.11.1-dev and reached the
  monitor under both SeaBIOS and UEFI.

## Remaining hardware limits

The installer still requires an x86-64 system, Secure Boot disabled, a
512-byte-sector AHCI or legacy IDE target, and PS/2/i8042 or COM1 input. It
does not yet install to NVMe, USB mass storage, 4Kn disks, software RAID, or
partition-preserving manual layouts.
