# NexOS v0.15.0-dev - NVMe and 4Kn storage

Milestone 15 expands the installable storage stack beyond AHCI, IDE, and USB
with a native NVMe driver and variable-sector installation support.

## Highlights

- Discovers PCI NVMe controllers and maps their BARs without Linux or another
  operating-system driver layer.
- Creates polled admin and I/O submission/completion queues, identifies the
  controller and namespace 1, and performs page-backed reads, writes, flushes,
  and bounded completion waits.
- Retries failed NVMe I/O after disabling and re-enabling the controller and
  recreating its queues. `diskutil recover diskN` exposes the same recovery
  path explicitly.
- Accepts active NVMe namespace formats with 512-byte through 4096-byte
  logical sectors and no separate metadata.
- Generalizes protective MBR/GPT writing, FAT32 formatting, NexFS access,
  partition inspection, `disktest`, and the guided installer for 4Kn media.
- Installs both legacy BIOS and UEFI boot paths on 512-byte media. 4Kn media
  uses a larger FAT32 ESP and a UEFI-only boot path.
- Adds `diskstress <disk> <rounds>` for bounded, read-only first/middle/last
  LBA stress and a published hardware-compatibility matrix.

## Release gates

- 79 host unit tests, strict workspace Clippy, optimized freestanding
  userspace, and a warning-free custom-target kernel build.
- Existing four-CPU BIOS/UEFI platform, AHCI install/no-ISO boot, and xHCI
  HID/hub/storage/disconnect regressions.
- QEMU NVMe namespaces using both 512-byte and 4096-byte logical sectors.
- NVMe Identify, boundary reads, explicit controller reset recovery, cache
  flush, and 256 stress rounds.
- Guided 4Kn installation followed by an OVMF UEFI boot from NVMe with the ISO
  removed, NexFS root mount, `/bin/nexsh` launch, and release-file readback.

## Current boundary

The NVMe driver uses one polling I/O queue and namespace 1. Multiple
namespaces, interrupt-driven queues, protection metadata, live NVMe hot-plug,
and legacy-BIOS boot from 4Kn media remain future work. Physical computers
must still disable Secure Boot and should be checked against
`docs/HARDWARE_MATRIX.md`.

## Next milestone

Milestone 16 will focus on real multiprocess execution: per-CPU kernel stacks,
TSS/syscall state, inter-processor scheduling, process spawn/wait, and actual
multi-process pipelines.
