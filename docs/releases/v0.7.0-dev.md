# NexOS v0.7.0-dev — Milestone 7 processes and VFS

This development release adds the first protected userspace execution path and
the portable process, scheduling, ELF64, syscall, and VFS foundations.

## Highlights

- Kernel and user GDT segments plus TSS ring-0 and double-fault stacks.
- User-accessible page mappings that retain supervisor protection for kernel
  leaves.
- x86-64 `SYSCALL`/`SYSRET` MSR setup and dedicated 16 KiB syscall stack.
- A real `IRETQ` ring-3 self-test that queries ABI v1 and exits safely to the
  ring-0 monitor.
- Versioned syscall dispatch with assigned register convention and negative
  error results.
- Fixed-capacity process table with PIDs, parents, state, current directory,
  address space, handles, exit, wait, and reap behavior.
- Five-tick round-robin scheduling, timer decisions, sleep deadlines, blocking,
  wakeups, FIFO wait queues, task exit, and reaping.
- Strict x86-64 ELF64 validation and load-target interface for `PT_LOAD`
  segments.
- Mount-aware VFS core with canonical path handling and longest-prefix mount
  routing.
- Monitor diagnostics: `ps`, `schedinfo`, `syscalls`, `usertest`, and
  `vfspath`.

## Verification

- All 36 host unit tests and documentation tests pass.
- Strict Clippy checks pass with warnings denied.
- The freestanding custom-target kernel links successfully.
- QEMU Q35 BIOS executes `usertest`, crosses ring 0 → ring 3 → `SYSCALL` →
  ring 0, reports ABI v1, and continues accepting keyboard interrupts.
- `ps`, `schedinfo`, `syscalls`, and `vfspath /home/../bin` return the expected
  process, scheduler, syscall, and canonical path information.
- BIOS and UEFI raw-image and ISO smoke boots reach the v0.7 monitor.

## Current limits

The kernel still boots into its diagnostic monitor. General executables from
NexFS, the userspace runtime and shell, file-backed VFS mounts, pipelines, and
Unix-like commands are milestone 8. Signals, demand paging, copy-on-write,
security hardening, and multi-processor scheduling remain later work.

## Release images

The prerelease provides a hybrid BIOS/UEFI ISO, a zipped 128 MiB raw disk
image, and a SHA-256 checksum file. Secure Boot must be disabled.
